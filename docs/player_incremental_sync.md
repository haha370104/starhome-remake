# 在线玩家复用与增量同步

2026-10-14迁入社区P01的工程能力，保留当前存档、领域规则和旧协议兼容路径。

## 所有权与事务

`AuthoritativeAutosaveService`保留既有记录/仓储兼容边界；`OnlinePlayerStore`按已接受的权威事实维护长期Player身份。
观察同一角色时对比完整字段事实，而非只比存档revision。因此同版本内技能经验、损耗、食品时钟也能正确刷新。
未变化的背包实例及装备复用；新状态映射失败保留原聚合；会话退出/过期释放投影。
该存储供查询和显式隔离事务读取，不能拿观察返回的Player直接执行写命令。

`PlayerTransaction`为已审查的背包操作创建候选：摆放、拆分只复制目标；合并和拾取复制同定义的潜在堆叠；整理复制整个背包。
候选的战车资源与成就状态独立，未写的装配/仓库等只读复用。新增用例必须先声明所有可能写入的组件及物品，不能把任意命令套进此快速路径。
`PlayerInventoryRecordWriter`只采集背包与采矿成就相关状态；其他记录组件共享至仓储的隔离复制边界，不能继续修改共享对象。
旧式空成长状态保持兼容，领域恢复后的语义与完整映射一致。

换装、商店、制造、仓库等跨域事务仍采用现有完整候选；仓储成功后才更新在线事实、战斗状态并发消息。
这是明确的保守迁移边界，没有把所有服务同时替换为共享可变Player。旧存档格式不变。
高频技能沿用 `PlayerSkillProgression` 局部隔离，升级持久化、失败和重入回滚的规则保留。
成就点缓存只在账本变化时失效；任务缓存比较任务状态、材料数量、技能、等级和日期，不用revision猜测进度。

定时保存采集最新权威状态后与最后已保存事实比较：未变化时不制造新revision；有变化才进入原存储事务。
磁盘仍默认60秒异步检查点，正常退出等待成功。没有把每次背包事务改回同步磁盘写入。

## 可靠增量与重同步

握手可声明 `player_change_version=1`。没有该字段的客户端继续收到完整投影；独立服和进程内传输共用发布器。
每个连接拥有随机同步代号、独立递增序号和完整基线；同步序号与事务revision分离。
首份、重新连接、角色切换及显式query发送全量；其余按组件字段差异传输，物品/技能行按稳定身份编码变化及最终顺序。
删除、空字典、空数组有明确含义。没有把全服掉落点击合并成一个防抖窗口。

客户端在隔离字典中合成完整候选，校验代号、连续序号、行身份和补丁格式后，再交给既有CurrentPlayer领域解析器原子接受。
重复消息不再次应用；缺包或无效补丁保留当前状态并只发一个全量查询，直到全量成功恢复。
原业务外壳继续传递，例如拾取结果、商店返回、任务提示；面板不依赖网络补丁格式。

CurrentPlayer使用独立PlayerPanelDecoder恢复候选，成功后一次接受并立即通知身份订阅者；界面级PlayerPanelSession通知仍在同帧合并。
解码候选不继承CurrentPlayer的信号及同步生命周期，避免在同一脚本内递归构造同类导致退出时的脚本资源残留。

每张地图每次发布构造一次公共实体/怪物/矿点/地面快照，再附加当前角色能源、武器、特殊能力及采矿状态。
公共生成与私有生成分开，传输仍采用原世界快照外壳，因此客户端预测及独立服协议不必同时推倒重写。
观察信号获得深拷贝，公共字典不受订阅者修改影响。

## 验证入口

- `tests/network/contracts/player_change_test.gd`：行增删、空状态、重复、断档、坏补丁、全量恢复、重连及旧客户端。
- `tests/server/player_panels/online_player_store_test.gd`：稳定身份、同版本经验、失败隔离、旧式字段兼容、脏数据保存、过期候选与采集重入。
- `tests/integration/in_process_authoritative_transport_test.gd`：真实业务已协商增量且正常还原；原业务断言保留。
- `tests/server/authoritative_server_smoke_test.gd`：公共/私有快照等价及连接隔离。
- 连拾396项、成长32项、后台存储17项、正常退出50项继续约束副作用与耐久性。

这组优化不会消除所有大背包成本：完整领域校验、必要的仓储记录复制和复杂装备事务仍会耗时；应以实际遥测决定下一步，不能为省时跳过校验。
