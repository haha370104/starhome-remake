# P6 智脑扩展

日期：2026-09-18。自动补给、炮导类别修正及生命周期停用已接通；装备方案和死亡记录仍在实施。

## 原客户端证据

- 免费版 `ven/ShortcutToolbar.fcc:1630–1669`：智脑包括攻击模式、自动拾取/攻击、
  自助快修、服装/玉坠提示、五行自助、装备切换和死亡记录。
- `wk/interface.fcc:718–808`：装备切换保存四套战车装配组合，各槽记录具体装备身份；
  `cltplayer/moveaction.fcc:3862–4068` 从已启用方案中轮换，装备必须实际在身上或背包，
  最终发送服务端处理。`great/wk_great.fcc:676` 的 `Aptitude042` 明确为30秒冷却。
- `yl/SmartSys.fcc:255–441`：自助快修提供按周期或生命阈值使用指定修复器，
  周期模式不低于30秒。它不是现有 Z 自维修技能，也不是已确认的普通食品/能量包算法。
- `ven/ShortcutToolbar.fcc:2605–2766`：死亡记录可查看、清除、导出，按最新在前显示。
  `mainclient_me.fcc:3754` 原文本是被玩家杀害；`ourgamestart.fcc:761` 原记录仅保存在会话。
  因而本次PVE记录及跨重启保留是明确的复刻扩展，不宣称原版已有。

## 本次实现边界

1. 保留自动攻击、身边拾取、自维修和炮导模式；炮导按实际导弹类别识别，不能只认新兵导弹ID。
2. 能量包与食品自动补给是本次已批准扩展。用户选择要使用的背包物品类型及阈值，
   复用手动 `use_inventory_item` 命令，保留能量包“不过量批用、余量不足一包时用一个”的规则。
   不由客户端增加能源、绕过锁定、冷却或食品的奖励切面。
3. 食品只使用用户明确选择的类型，检查是否需要补体力、续已有到期增益或恢复生命，
   避免每次心跳消耗食物；类型耗尽、锁定或同类效果冷却时等待，不擅自换成另一种。
4. 战车方案保存四套实际实例与槽位；保存不移动装备。应用时整体预演所有来源、槽位、
   锁定、背包空间与当前地图资格，一次提交，不连续发送多个单件装配命令。
   保留当前野外不可更换底盘的限制；不引入飞船或人物服装方案。
5. 切换方案保留30秒冷却及现有武器/能量时序，保存冷却截止时刻，重启不能刷冷却。
   方案中的装备卖出、分解、存入仓库后明确报缺失，不能按物品名自动替换另一实例。
6. PVE击毁记录从权威战斗事实产生，记录时间、地图与有依据的来源；无法确认的原因不编造。
   记录只供查看，不参与奖励或任务。提供本角色本地记录及明确的清除操作。
7. 死亡、切图和重新进入游戏停用自动操作，保留选项但必须手动再次启用。
   手动行走、输入锁定和正在维修仍按既有规则暂停攻击；失败重试节流。

## 已完成：自动补给与停用

新增指定能量包、指定食品/修复器、储备能量及体力阈值；未选择时不代选，耗尽时保留选择，
可以跨同类型堆叠寻找未锁定物品。普通食品按体力或所带效果到期补给，即时修复沿用生命阈值。
控件发送设置，策略选择实例，控制器提交现有`use_inventory_item`，数量、效果及实际扣料仍在服务器。
城区手动启用后也可补食品供生产使用；自动攻击、自维修仍限战斗地图。
补给两秒重试节流，等待回包不预测消耗；死亡和切图立即停用并同步面板开关，后续恢复生命不自动重启。
炮导识别实际`VehicleWeapon`导弹模式，所有已启用导弹均可参与，火箭和工程臂不混入。
