# 非多人玩法补齐计划

日期：2026-09-17。计划基线：`56544c1`。
依据：[原版功能缺口核查](original_feature_gap_audit.md)。
用户要求：多人游戏交互相关先不处理，为其余功能制定开发计划。
实施基线：`1.0.0` 标签（`c9dcdb83f7f663971e4087cf7c971f286e5af7d4`）。
用户已批准开发；P0 首批准备、P1 与 P2 已完成，接续 P3，之后依次 P4 → P6 → P5。
P1 实施与验收见[战车加工台账](vehicle_workshop.md)；不能将规则核查计作玩法交付。
P2 见[普通属性加工](equipment_processing.md)和[耐久维护/磨损/弹药](equipment_maintenance.md)，包含实际运行、权威交易、保存与窗口验收。
P3-A [萤石/耀石](extra_attribute_processing.md)已完成完整流程；接续 P3-B 能量石与护甲，之后 P3-C 服装、P3-D 分解转移。

## 1. 范围

纳入：战车与人物装备成长、耐久维护、对怪物有效的装置能力、个人仓库、生产、智脑、
系统设置、单人可完成的日常/PVE活动，以及后续独立的太空玩法。

暂缓：队伍、好友、聊天/私聊、玩家交易、信件/留言、组织、公会仓库、婚姻、PVP、
竞技房间、城市争夺/组织经营、多人伤害排名及其奖励、维修臂治疗其他玩家。
正式账号/多人生产数据库等上线工作不作为本次玩法主线的前置条件，继续使用现有仓储端口。
现有进程内/ENet权威链保留，各项新玩法不能改成客户端自行结算。

以下边界需要特别保留：

- **个人仓库不属于玩家间交互，纳入计划。**不扩展成账号共享或公会仓库。
- **召唤守卫延期。**免费版HUD的 `CreateOneNpc` 调用 `CallRedNameNpc`，后者位于
  [npcmeclt.fcc](../../starhome_lz_fr_fcc_source/dcz/npcclt/npcmeclt.fcc)第35行起“攻击红名的npc代码”，
  并发送 `r_PlayerSoS`。不能直接改成新的PVE宠物；现有图标保留。
- 特殊装备的常驻属性和PVE效果先做；原文明确只对其他玩家生效的吸收、追加伤害和套装技能延期，
  UI明确显示其适用范围，不能把未实现的玩家专属效果自动套给怪物。
- 隐身/雷达先核实怪物索敌、探测的原版关系；如果某项只有PVP用途，该项延期，不创造新的怪物能力凑用途。
- 之前删掉的HUD入口与大厅NPC继续保持；新增加工入口优先从装备详情、背包右键和已有城区设施接入。
- 成就、人物原创前缀/特性/宝石、紫晶、接合器槽位与强化预算、变异/BOSS规则均沿用已确认设计。
  原版服装改良和战车晶石不会覆盖这些既有系统。

## 2. 顺序与依赖

先让现有掉落物有用途，再补装备能力和后期内容。每个子阶段都交付可操作、可保存、
有权威结算的完整流程，不攒到整期结束再验收。

| 阶段 | 交付目标 | 主要依赖 | 规模判断 |
| --- | --- | --- | --- |
| P0 规则与数据准备 | 首批装备资格/消耗/效果表、材料用途台账、存档兼容方案 | 当前核查 | 小；随各阶段继续完善 |
| P1 战车开槽镶嵌 | 开槽、镶嵌、摘取、裂纹、同类上限、符合资格装备的扩孔 | P0对应规则 | 中 |
| P2 基础加工与耐久维护 | 车炮引擎属性加工，维护/速修，再接磨损 | P1的实例状态和属性接缝 | 大，拆两次交付 |
| P3 进阶加工与材料回收 | 萤石/耀石/能量石、品质、护甲精工、服装改良、分解/属性转移 | P2 | 大，按加工类型拆分 |
| P4 PVE装置与表现 | 发生器，原版支持PVE的隐身/雷达，缺失特效核对 | P0效果规则；与P2/P3无强依赖 | 中至大 |
| P5 特殊装备与中枢 | 晶源体、奥斯格兰、撒玛、中枢的成长与PVE能力 | P1/P3/P4 | 很大，四个独立子阶段 |
| P6 日常体验 | 个人仓库、批量生产、智脑补全、系统设置 | 仓库接P1/P2状态；其余依对应能力 | 大，可按子项提前安排 |
| P7 PVE活动与任务覆盖 | 原版指定队长/单人可玩活动，扩大佣兵/历练可完成范围 | 装备成长、材料用途与PVE能力稳定 | 大，按一个活动一轮交付 |

用户确认的本次执行顺序：**P0 → P1 → P2 → P3 → P4 → P6 → P5**。

P7、P8 不在本次实施范围。这里没有排定日历工期，原服未知规则和素材缺口会影响工作量。

## 3. 分阶段任务与验收

### P0：把规则和获取链写清楚

交付：首批装备/材料对照表、规则来源标记、存档迁移方案及可复现的测试装备样本。
先覆盖P1所需内容，后续阶段各自补表，不先造一套承载所有功能的大框架。

1. 每条规则标记“原客户端明确”“用户已指定”“复刻拟定”“尚待查证”，区分荣耀/免费分支。
2. 每种启用材料记录获取方式、消费方式和关联功能；已可掉落但暂无用途的物品明确列出。
3. 规则数值进入版本化配置，领域对象负责校验；新增状态只保存孔槽/加工等原始事实，不保存重复叠加后的属性。
4. 普通装备加工、普通晶石、专属符文、晶源核、人物原创宝石分别建模，只复用稳定的交互组件。

验收：P1可处理的装备、材料、失败结果都能在表中找到；旧存档缺少新字段时有明确默认值。

### P1：战车开槽、晶石镶嵌与摘取

交付分成三步，每步包括领域、存档、服务和界面：

1. **开槽与六类晶石**：装备资格、柔解剂消耗、孔位选择、镶嵌、数值生效；接入当前瑕疵/明亮材料链。
2. **摘取与裂纹**：摘取回包、背包容量、裂纹持久化、损毁确认；精密锤核实其适用分支后接入。
3. **扩孔与完整覆盖**：补有明确资格的第9/10孔；处理全身同类最多四颗、不同品质混用和暴击属性。

规则准备项：逐装备孔数/资格，开槽概率及失败消耗，四颗生效的选择顺序，暴击叠加，扩孔/摘取工具。
客户端无法确认的规则先形成明确的复刻方案，不能悄悄填常数或宣称来自原服。

验收：同一装备在背包、装配、卸下、仓储往返和重启后孔槽一致；同类第五颗不额外加成；
攻击、生命、防御、暴击由服务端实际生效；摘取/背包满/重发不会丢失或复制物品。
这里的“仓储往返”指现有存档仓储，个人仓库在P6单独验收。

### P2：普通装备加工与耐久维护

**P2-A 基础属性加工**：先车体、能量炮、引擎，再扩展有原版依据的其他装备。
保存各项加工值与上限，界面给出前后对比、材料/金币消耗及失败结果；输出功率加工接入真实能源恢复。
与接合器强化的等级、配方和预算分开，不重用其规则来代替普通装备加工。

**P2-B 耐久维护**：先交付可用的维护/速修和材料消费，再启用对应磨损。
分别核实普通装备、护甲、服装、特殊装备能否修理、维修是否影响耐久上限、损坏时哪些属性失效。
不能把现有通用 `repair` 方法直接用于原版明确不可修复的装备。

验收：加工后面板/射击/能源一致；换装与重启不丢加工值、不重复加成；维修材料和金币原子扣除；
损坏到修复的属性恢复正确。磨损不得早于修理流程和材料获取链开放。
重测已确认的同档车炮四五秒连续输出，新增强化不能重置射击冷却或错误补满能量。

### P3：进阶加工、服装改良、分解与转移

分四个子阶段：

1. 萤石/耀石等原版额外属性加工，分别保留适用装备和属性上限。
2. 能量石相关品质加工/合成、护甲精工及独立强化。
3. 原版服装改良，与现有前缀/特性/宝石共同计算，但分别保存成长状态。
4. 装备分解、模块属性吸取和转移；说明哪些加工、晶石、符文会保留、返还或消失。

每个子阶段同时补齐其必要材料来源、说明、预览和操作入口；不一次性开放所有尚无规则的配方。
分解与转移涉及孔槽和成长状态，应最后做，并对已镶嵌/已锁定/已装配物品给出明确处理规则。

验收：失败不部分扣料；目标不兼容时不消耗源装备；转移无复制；分解产物有容量校验与可追溯操作结果。
原版材料和复刻原创强化石身份保持独立。

### P4：现有装置的PVE能力及特效

1. 按发生器原类别实现实际触发、能量/冷却、伤害或状态效果，接入现有两件装配上限。
2. 核对隐身/雷达对怪物的适用关系；有依据的部分接入怪物索敌、显隐与侦测接合器，纯PVP部分延期。
3. 核对剩余9种怪物命中特效及新装置需要的表现。能证实的补齐；证据不足者保留具体缺口，
   不用身体动画或任意同色爆炸凑齐，也不让未解的个别映射阻塞其他装置交付。
4. 维修臂对其他玩家维修仍延期；只有确认原版支持的非玩家目标才另外接入，不能默认给自身回血。

验收：一次攻击只触发一次、服务端决定结果；卸装/死亡/切图清理临时状态；移动开火时炮口和受击位置正确。
状态计时不集中制造性能尖刺，新效果使用共享资源，不为每只怪物重复加载。

### P5：特殊装备与中枢，逐套完成

1. **晶源体**：品质、成长、三孔晶源核与常驻属性；先做规则较独立的一套。
2. **奥斯格兰**：成长/祝福、每件两枚指定符文、明确可用于PVE的减伤/回血；保留套装条件数据，
   原版只对玩家触发的附加伤害/套装技能延期，不改成打怪触发。
3. **撒玛**：基础成长、聚能穿透、脉冲、核变等对可攻击目标的PVE效果；针对其他玩家的扰流器效果延期。
4. **中枢**：先确定原版桥接芯片/装备成长中可用于PVE的范围。此前“可能做成技能点”尚非定案，
   若选择技能点改造，需先给出独立数值与重置方案，再实现，不能混称原版复刻。

每套都交付获取→成长→装配→战斗→保存的完整流程，并单独核对数值与当前地面装备跨度。
旧版本中动辄数万的效果不直接混入当前低数值环境；调整值明确标为复刻配置。

验收：不同系列共存、独立槽位、正确的加成顺序；技能概率/冷却/触发目标有专项验证；
界面明确区分已经生效的PVE能力和延期的PVP能力。

### P6：个人仓库、生产、智脑与设置

这四项分开交付，不做一个同时改背包、战斗和设置的大提交：

| 子项 | 交付内容 | 验收重点 |
| --- | --- | --- |
| 个人仓库 | 物品存取、堆叠、容量/扩容、实例状态完整保存；入口复用背包或既有城区设施，地点限制由服务端校验 | 孔槽/加工/裂纹/原创人物强化不丢失；存取失败不复制物品；未引入共享仓库 |
| 生产 | 批量次数、投入倍率的原规则核对、加工等待/队列、进度与取消处理 | 材料预留/扣除和返还只结算一次；背包满、切图、退出/重启、计时和经验倍率正确；不凭空修改现有成功率 |
| 智脑 | 自动能量包/食品补给、死亡记录、装备方案切换；仅对已实现的装置开放额外模式 | 复用手动操作与能量包批量规则；不绕过冷却/锁定/材料限制；切换方案原子校验；死亡/切图停用 |
| 系统设置 | 热键、字号/可读性与颜色选项、音乐音效设置、正常退出；已有音源先核查再接音量 | 偏好重启保留、输入冲突可恢复默认；仍使用统一字体；退出完成保存；没有音源不伪装成已有完整音效 |

网速测试仅列为后续诊断便利项，不阻塞单人玩法；信件、留言随多人延期，已删帮助入口不恢复。
个人仓库、自动补给和正常退出具有直接价值，建议优先于这一阶段其他便利项。

### P7：可单人完成的PVE活动与日常覆盖

1. 为佣兵未开放条目按“无怪物、无材料链、依赖活动、依赖多人”逐项归因。
2. 先补有可靠原版定义的指定队长/普通PVE目标及必要材料来源，再安排单个活动地图和BOSS战。
3. 一个活动先完成入口、开始/结束、失败/恢复、奖励和存档，再接对应佣兵/历练。
4. 佣兵积分的额外奖励/用途单列设计：有原版依据的按依据补，无依据的先出复刻方案；紫晶币种与
   每日领取200/完成100保持。不能把缺少的多人伤害排名改成“击杀即完成”以凑495条全开。

验收：每个新开放任务真实可完成，奖励经既有奖励切面入账；跨日/重登/重复击杀/重发不重复发奖。
定时事件按活动地图状态推进，补怪和寻路错峰，不重新引入每一两分钟的集中卡顿。
原版活动与用户已有的变异/BOSS规则分别登记，互不覆盖。

### P8：太空与飞船，作为独立扩展

先核查一套可获取飞船/装备、一张有可靠地图与资源的太空区域和对应怪物。
首个可玩版本只覆盖地面进入→飞船装配→移动/开火→掉落→返回地面的完整流程；
之后再扩展地图、生产、飞船成长和相关任务，不以大批导入素材代表完成。

验收：地面/太空装备状态分离、往返与保存一致、现有战车世界渲染不受影响。
此阶段不恢复用户已删除的“星系探索”按钮，也不包含太空PVP。

## 4. 每阶段共同的工程要求

- **充血领域模型**：装备拥有自身孔槽/成长/耐久行为，Player协调背包与装备的一致性；
  应用服务编排事务，界面只展示和提交意图。规则不回填到 `main_hall` 或一个万能强化服务。
- **计算与存档一致**：同一装备实例、同一权威属性计算；操作后更新真实战斗与UI，
  只持久化原始状态。新增字段有旧档迁移和往返测试，测试使用隔离存档。
- **既有切面继续使用**：新材料掉落和技能经验走统一奖励链；食品不另写倍率入口。
  战斗能力保持独立的效果/触发职责，不把开孔、交易和状态效果塞进奖励切面。
- **事务**：复用库存版本和服务器提交边界；自动保存不令无关确认失效；重复请求、失败扣款、
  背包满、锁定物品和换装冲突有实际回归。长期计时不用客户端计时器决定奖励。
- **原UI与素材**：先复用原图和已提取组件，保留统一字体、窗口堆叠上下文；遵循既有素材授权和溯源规则。
- **验收**：相关领域/权威事务/存档测试，两种传输的必要接缝检查，真实UI与战斗表现检查；
  改到战斗循环、队列或刷怪时补相应性能检查。阶段完成以实际跑过的覆盖范围为准。
- **提交**：按独立可验收步骤提交，单次最多20文件、文本增删合计2000行；素材先独立提交再更新gitlink。
  文档同步记录规则、已实现部分及仍延期部分，不以“类/窗口已存在”关闭待办。

## 5. 第一批具体开发包

下一次开始实施时从P0/P1开始：

1. 核实当前启用装备的开槽资格、初级/高级柔解剂适用范围、六类晶石和各孔规则，输出可执行规则表。
2. 实现装备孔槽实例与旧存档迁移，接入普通开槽/镶嵌事务及实际属性计算。
3. 从装备详情/背包右键打开独立战车加工窗口，完成可视孔位、材料选择、效果预览和确认。
