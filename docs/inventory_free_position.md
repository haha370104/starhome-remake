# 背包自由坐标规则（2026-09-07 确认）

本说明取代旧面板文档中的“矩形不得重叠”“15 像素吸附”和“每次回包自动排格”规则。

- 背包位置仅由物品的 `position_px` 决定，界面直接显示该坐标，服务端原样保存；允许两个或多个不同物品完全重叠。
- 拖动不自动吸附、不交换物品、不挤开其他物品，不改变物品数量或身份。
- 只有点击「整理背包」才按稳定实例 ID 排列，坐标对齐到五列八行虚拟格子的左上角。背包区域为 276×295，索引 0..39 对应 `(floor(col×276/5), floor(row×295/8))`。
- 容量仍为 40 件/堆叠，身份唯一性、容器、坐标边界、锁定和 revision 校验继续生效。允许重叠不放宽这些规则。
- 图标继续使用统一的显示尺寸及 5px 内边距，和其自由摆放坐标是两个概念。重叠时后绘制的物品接收鼠标，可以先拖开上面的物品。
- 新拾取、购买或卸下的物品优先放在未被现有图标覆盖的虚拟格子，不重排原有物品；若自由摆放遮住了所有格子但未满 40 件，仍允许选择默认坐标放入并重叠。
- 旧存档 `footprint_px` 暂保留兼容，但不再参与重叠拒绝、布局容量和坐标边界计算，无需删除或重建存档。

## 手势修复

之前每次左键松开都会发移动命令，包括只想单击或双击装备的情况；同时客户端显示顺序格子、服务端保存像素位置，两个坐标体系不同，导致频繁出现 `inventory items overlap`。

现在左键移动达到 5px 才认定为拖动。单击、轻微抖动、双击后的松开都不产生移动命令；双击只产生装备意图。真正拖动保持抓取点偏移，松开只提交一次坐标，预览恢复后等待权威回包，拒绝时也不会残留错位图标。容器外落点取消拖动。

实现仍通过 `Inventory.move_item()`、`InventoryLayout` 维护充血领域规则与 revision；未增加客户端单独持久化或绕过服务端校验。
