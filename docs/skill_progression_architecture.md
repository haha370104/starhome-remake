# 技能成长与综合等级实现

## 1. 规则边界

技能成长由权威服务器结算。客户端只能发送移动、攻击或生产意图，不能提交技能经验、技能等级或
综合等级。当前启用 13 项技能：驾驶、能量炮、导弹、火箭炮、隐身、雷达、采矿、维修、制造、
加工、提炼、裁缝和烹饪；飞行器保留稳定 ID，但首版不显示也不参与综合等级。

`SkillBook` 持有每项技能的 `SkillState`：

- `level`：基础技能等级，不含服装临时加成；
- `current_exp`：当前等级内的整数经验；
- `fractional_exp`：不足一点的经验余量，范围为 `[0, 1)`。

升级门槛来自 `data/gameplay/skill_progression.json`：

```text
L = min(当前技能等级, 700)
需要经验 = floor((L + 1)^2 × P(L) / 100)
```

每一个玩法事件独立发放一次经验。达到门槛时只提升一级，随后整数经验、小数余量和所有溢出
一并清零，禁止把批量生产或范围攻击合并成一个可连续跨级的经验池。

## 2. 已接入经验来源

```text
服务端认可的移动位移 ─┐
                       ├─> AuthoritativePlayerPanelService
最终有效武器伤害 ──────┘       -> Player.grant_skill_experience
                                  -> SkillBook / SkillProgression
                                  -> 综合等级重算（仅升级时）
                                  -> PlayerStateRecord
```

- 能量炮：只消费 `energy_cannon_hit` 的最终 `applied_damage`。未命中、免疫、零伤害、弹体过期和
  发射动画均不发经验。默认倍率为 `1 点有效伤害 = 1 点经验`。
- 驾驶：只累计 `AuthoritativeMapInstance.simulate()` 经静态导航和动态碰撞校验后真正接受的位移。
  经验原始量为 `距离 × min(整车重量, 计重上限) / 驾驶经验单位`。首版单位为 100000
  重量·像素、计重上限为 1000；受阻回滚、传送、地图切换和位置纠正不经过该事件入口。
- 其余技能：领域层和 `authoritative_action` 服务端入口已经统一，待采矿、维修、制作、隐身、
  雷达、导弹和火箭炮玩法模块落地后逐个接入客观结算事件，不能从 UI 按钮点击直接发经验。

进程内调试模式运行真正的 `AuthoritativeServer`：地图实例产生内部事件，服务器应用技能成长，
仓储保存玩家聚合，再通过与 ENet 相同的消息契约刷新客户端。因此客户端不存在离线经验公式、
离线面板状态或额外提交时机。

## 3. 综合等级

综合等级由 `Player` 在技能升级成功后重算并与技能状态放在同一聚合中持久化：

```text
综合等级 = 10 + floor(Σ max(0, 技能等级 - 10) × 技能权重)
```

驾驶和能量炮权重为 0.50；导弹、火箭炮为 0.35；采矿、维修为 0.30；隐身、雷达为 0.25；
加工、提炼、裁缝、烹饪为 0.20。制造和飞行器的原版权重尚无可靠证据，目前明确配置为 0，
并列在 `unconfirmed_weights` 中，后续只改服务端配置即可回归。装备提供的技能加成不参与永久综合
等级，避免穿脱装备改变门槛身份。

客户端人物面板只显示服务端投影的“综合等级”。技能窗口复用荣耀版 `MinForm`
素材，保持 `240×375` 原像素尺寸，且是不会阻断窗外地图操作的普通游戏窗口。三列分别为
技能名称、技能等级（基础等级与装备加成合并表达）和当前经验百分比。详细经验值仅在悬浮
说明中展示，客户端不在本地预测升级。服务端以“可见百分比是否变化”决定是否立即推送
新面板快照，因此小数驾驶经验不会被整数截断隐藏。

## 4. 持久化与提交时机

文件存档 schema 2 把旧版整数技能等级迁移为 `{level, current_exp, fractional_exp}`。SQLite 生产
结构对应 `002_skill_progression.sql`，增加综合等级和小数经验列。

- 普通经验变化先更新 `AuthoritativeAutosaveService` 的权威内存副本，并随三秒自动存档提交；
- 技能升级及其综合等级变化立即调用 `commit_player_state` 落盘；
- 面板装备事务会从包含最新技能进度的内存聚合开始，避免换装覆盖尚未自动保存的经验；
- 客户端只在服务器发布的新面板快照中看到确认结果。

## 5. 扩展新玩法的约束

新的技能来源必须在服务端模块产生一个不可由客户端伪造的客观事件，然后在
`AuthoritativePlayerPanelService._experience_from_event()` 中配置换算。若一个批次包含多次独立
成功动作，调用方必须逐次发事件，以保留“一次最多升一级”的原版语义。持续伤害默认不得重复给
武器经验，除非后续取得原版服务端证据。
