### 植物园可发现性修正（同日反馈）

采摘点是选定的15处，不是场景中每一株装饰植物。原先缺少悬浮检测和位置标识，只有菜单选中才亮，北侧空白区域尤其容易被误认为没有玩法。
现与地面掉落共用4px绿色晕染，鼠标悬浮果实或名称即可高亮，按实际纹理尺寸及图集帧边界命中；菜单选中与悬浮独立。
名称常显“可采摘 / 生长中”，隐藏果实不保留图片命中。Tab地图显示15个“采摘”目的地，可经现有权威移动链路自动前往。
活动世界只接收模块提供的MapNavigationPoint快照，切图释放，不依赖植物园业务对象。
新增 `botanical_garden_transport_test.gd` 已纳入两个测试入口：真实进程内传输从城市入口切图、导航接近、采摘入包、更新冷却及拒绝重复领取，9项断言通过。
场景专项22项断言和GPU截图通过，覆盖实际鼠标输入、移出取消、名称命中、菜单选中、图集边界和切图清理；导航原有22/20项与采摘权威27项回归通过。
这些是本次针对反馈的复验，下面186项为前一轮历史记录；本次未重新执行全套门禁。

## 工程能力

P01 的协议、事务所有权和保守边界见 [玩家增量同步](player_incremental_sync.md)。
在线 Player 保持稳定身份；拾取、整理、移动及堆叠按背包/物品写集合隔离；采矿成就与入包一同提交。
成就积分及任务进度按事实变化缓存；无变化角色跳过重复保存；技能小数仍走已有高频成长边界。
完整写盘检查点和正常退出等待策略保留。换装、制造等跨域用例继续完整候选校验。

P02：客户端与服务器导航缓存分别保留最近2张；纹理LRU预算256MiB（估算值，不等于进程或GPU总内存上限）；
包内图片由低优先级线程读取/解码，纹理上传在主线程，队列有去重、容量和退出回收。
怪物创建仍遵守每帧10个预算，复用同种怪物视图，空闲池上限64；飘字空闲池上限128；
地面物品、矿点和动态实体使用空间候选，保留精确命中及原顺序判定；发生器状态不变时不重新建图。

P03：性能遥测默认关闭，启用方式、线程和基准见 [性能工具](../tools/performance/README.md)。
没有用社区作者的机器结果推断本机收益。

| --- | --- | --- | --- |
| 1 | 安全屋 / NFT_BT，blackroom | 1008,600 | 无 |
| 2 | 勇者之路 / NFT_BT，yzzl | 1008,1008 | 无 |
| 3 | 孟多拉城基地大厅三层 / NFT_DS，RoomSvr3 | 960,960 | 通往城市，标记408,348，接近点480,370 |
| 4 | 勇者之路 / NFT_SK，yzzl | 1008,1008 | 无，与序号2共用同一套场景 |

出生点取导航网格中靠近地图中心的可走位置，是复刻推导值。上述地图均未发现有效入站边，不能给出从基地走入的正常路线。

在主项目根目录运行 [实测启动器](../tools/manual_map_test.py)：

```powershell
python -X utf8 tools/manual_map_test.py
```

输入1～4进入，关闭游戏后返回选图，输入q结束。工具优先使用`GODOT_EXECUTABLE`或PATH中的Godot，
Windows下载目录仅有一个Godot控制台程序时也可自动识别；其他情况明确指定：

```powershell
python -X utf8 tools/manual_map_test.py --godot "C:/path/to/Godot.exe"
```

每次使用新临时角色及独立设置目录，正常玩家存档不会被读取或覆盖；测试存档、日志位于`.godot/manual-map-tests/`。
它通过正式客户端及进程内权威服务器进入地图，不是只显示底图的预览器。出生装备为默认角色装备。

建议实测：点选地面行走、墙体和楼梯边缘是否挡路、人物位置是否与小地图一致；按Tab点地图寻路，观察视角移动时贴图是否缺失。
序号3额外在Tab侧栏选择“通往城市”，应进入`glory_nft_ds_city1svr`；没有已验证的返程到三层路线，重新运行序号3即可。
没有出口的三条记录直接关闭窗口返回选图，不必修改主存档或人为放置传送点。

本次逐张使用`--map 1`至`--map 4`配合`--verify`验证了真实会话、短途移动和正常保存退出；
序号3还实际走完原出口切到城市，使用GPU运行并检查截图。`--capture`可保存画面到同一测试目录。
这些验证只覆盖本轮补图入口，不等于全套游戏回归。HomeSvr住宅地图和未选定的F07原版固定矿点仍未补齐。

`python tools/recover_glory_map_gaps.py` 默认只审计，`--apply` 才重建选定增量。
[解码工具](../tools/recovery/README.md)迁入PKH、ALE/RLE0/AEX、FCC包装器和索引解析，修正社区算法的RGB565取整、稀疏行推进及AEX逐帧色键问题。
497份PKH逐字节对照通过；8组两版本/三格式精灵共213帧与既有解码逐像素、原点一致。
FCC原生解码仍需合法本地DLL，本环境没有DLL，未宣称已完成此部分运行验收。

另修复已存在的物品登记漂移：当前1686个运行物品全部覆盖，新增402条显式复刻登记，原登记ID零删除。
可用 `python tools/build_known_content_registries.py --items-only` 重建；原版证据与复刻定义来源分开保存。
