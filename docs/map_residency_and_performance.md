# 地图按玩家驻留与模拟性能

## 加载边界

服务器启动只读取轻量地图路由/定义索引，不创建导航图、怪物种群或矿源。
玩家首次进入（含登录恢复、普通传送、击毁回城）才调用 `ensure_runtime_map`。
同图多个玩家共用一个实例，不按玩家重复创建地图。

每个逻辑 tick 开始前，注册表把无人且在途事务已结清的地图移出活跃集合：

- 停止地图 tick、怪物 AI、游荡寻路、采矿计时和种群补充；不向客户端发送空图快照。
- 释放 `DiamondNavigation` 和采矿模块持有的导航引用，解除战斗模块的地图回调。
- 只保留休眠领域状态：怪物位置/生命、矿点余量、地面掉落、时钟与生成序号。
- 返回时重新加载导航并恢复回调，不重新生成整张图。休眠期间不逐 tick 重放，
  只补算经过时间与刷怪/补矿周期，避免来回切图刷新血量或刷满已采过的矿。

休眠仍保留少量业务状态对象，并不等于销毁地图的全部数据；否则返回时会重置资源。
当前状态保留范围是本次服务器进程，尚不等同于地图世界状态的数据库持久化。

## 两个例外

1. 短线重连宽限期内，服务器仍保留玩家实体，因此这张图仍活跃；宽限结束移除实体后休眠。
2. 最后一个玩家离开时若有在途炮弹/怪物攻击或采矿事务，地图短暂继续结算。
   此时不再执行怪物 AI、发起新攻击或游荡，结清后下一 tick 休眠。

地图注册表的 `all_instances`、按实例 ID 和按地图 ID 查询只返回活跃实例。
调用方需要入图时必须走 `ensure_runtime_map`，不能直接取得休眠对象后使用其导航。

## 回归

`tests/server/map_residency_test.gd` 覆盖启动零实例、同图两人共享、最后离开释放导航、
导航弱引用回收、六分钟空图不模拟、回来保持血量/矿量/掉落、按周期补充以及在途攻击阻止休眠。
同时回归权威服、传送、击毁回城、采矿、存档恢复。

这些是服务端模拟边界；客户端当前地图的纹理生命周期是另一层责任，不应把缓存的图片
或挂载内容包索引与“后台仍在模拟其他地图”混为一谈。

## 游荡/返巢寻路退化

另一个独立问题：怪物绕障碍暂时越过游荡半径后开始返巢，一跨回边界又继续原游荡目标，
两个方向交替且每次都重建路线。D03 同一只怪物在约 50 秒模拟内请求了 764 次路线。

`MonsterLifecycle` 现在持有显式返巢状态，返巢途中不被游荡半径或重新索敌打断。
抵达家点后清除旧目标并等待正常游荡间隔；失败路线也按该间隔重试，不每 tick 反复寻路。
这不改变怪物的主动攻击/被动反击/不攻击分类，也不改变移速、数量、伤害或弹道。

2026-08-31 无画面 CPU 探针：D03、100 怪物、一个固定玩家、20 Hz 模拟，关闭网络与存档。
修复前 45 秒墙钟只算完 998 tick，平均 45.11 ms、P95 119.28 ms；修复后
1,200 tick（60 秒模拟）耗时 1.12 秒，平均 0.94 ms、P95 1.48 ms。
这是模拟耗时，不包含客户端纹理加载与 GPU 渲染，不能直接换算为最终帧率。
