# 复刻对齐方法与验收方案

更新：2026-09-14。本文约束“如何修复”，不是宣称所有视觉/规则已还原。
代码现状见 [交接](project_handoff.md)，具体证据见 [原客户端阅读指南](original_client_reading_guide.md)。

## 1. 对齐的四个维度

| 维度 | 原客户端可提供什么 | 新工程的责任 |
| --- | --- | --- |
| 视觉 | 帧顺序、调色板、原点、窗口坐标、图层、字体、调用参数 | 保留源语义并做原生尺寸渲染，检验截图和重合成 |
| 交互 | 按键、窗口状态机、命令调用、对象回调 | 保留确认过的操作手感，不照搬旧引擎的对象管理缺陷 |
| 规则 | 装备表、显示公式、客户端前置检查、部分配方 | 把已确认规则落实到共享领域；未恢复公式做有证据标签的配置 |
| 权威与可靠性 | 原端发送/接收字段及预测行为 | 服务端决定长期状态和结果，具备失败回滚、去重、重启恢复测试 |

每项结论必须标为【客户端证据】【用户确认】【复刻规则】或【待验证】。
源码里出现数值不等于服务器最终采用该数值；本地爆炸、扣能量预测也不允许照抄成客户端权威。

## 2. 一次修复的标准流程

1. **记录现象**：版本、地图/变体、坐标、装备实例/定义、行为、窗口像素尺寸、预期与实际。
2. **冻结证据**：保留源文件路径/符号/参数、资源帧元数据、截图、必要的命令/事件日志。
3. **定位分叉**：区分原件缺失、解码错误、映射错误、模型状态错误、网络时序错误和渲染错误。
4. **寻找共有原因**：同类素材复用 profile/组件；同类规则进模型/权威服务，不堆实体 ID 或世界坐标特判。
5. **先补反例测试**：至少一处报告点、一个同类实体、一个不应受影响的邻接功能；有状态问题补重启/重发。
6. **实施最小完整修改**：生成器→目录→模型→服务→投影→视图按需修改，不绕开中间契约。
7. **验收**：自动数值/几何检查 + 必要的真实渲染 + 两种传输接缝；只报告本次确实执行的范围。
8. **沉淀**：专题文档写来源、实现选择、遗留缺口、测试命令；登记索引、分批提交。

## 3. 地图：三个问题分别验证

- **静态叠图**：FCC 有效指令顺序、注释状态、origin、TLE/overdata；离线重合成对比像素及哈希。
- **可达性**：PKH 三字节单元的 `flags & 0x80`、坐标变换及 SetGoFlag；不用 PNG alpha 代替碰撞。
- **动态遮挡**：人物/服装/翅膀视作整体，以脚点对物件语义基线排序。
  楼梯的踏板与扶手需资产局部 profile；不能整张楼梯同一 Y，也不能按屏幕行随意切图。

重要限制：精修地图的 owner/语义层方案不等于已覆盖所有内容包地图；部分包仍用压平地板。
新图必须独立检查有没有前景数据，不能仅因能装载便宣称角色遮挡正确。
传送图像应在地面层，车始终盖住它；保留原 as/jt 绑定、帧序和方向，避免静态首帧重复烘焙。
传送关系的图标位置、接近点、目标入口号和实际出生点分开记录；返程重建明确标注导航推导。
`H10` 等字母数字名称是合法野外名，不能当乱码修正。

基准点：大厅楼梯及高台 `(840,420)`、`(1032,852)` 一带，楼梯角色/翅膀前后遮挡；
先按当前地图/版本复现，不把旧免费版坐标当荣耀版测试真值。
详见 [地图管线](map_resource_pipeline.md)、[阶段 2 历史证据](stage2_map_graph_seed.md)。

## 4. 角色、战车、物品与矿物

- 八向仅决定播放哪个方向；实际移动可沿任意直线，无遮挡一段内固定最近朝向，不走方格折线。
- 速度、帧率和步距一并校验；玩家可配置，NPC 不直接引用玩家实例配置。
- 车身运动朝向与炮口瞄准分离；开火不清空未完成移动路线。
- 人物裸模+固定服装槽共享同一个装配聚合；面板与世界使用各自正确动画，不复制装备状态。
- 物品 `inventory/dialog/world` 三种展示不能混用；原生图片尺寸不是背包占位尺寸。
  地面与背包使用同一个实例身份，不能通过另造简化物品修补显示。
- ALE/RLE/ACT 先查索引色、透明度、origin 和帧块。发黑需区分解码、调色板与 shader 重复乘色；
  已遇到纹理颜色被乘两次的回归，不能直接把图提亮掩盖。
- 矿源不同样式由配置/权威矿源种子确定，客户端不每帧随机；解析出多帧不自动等于播放动画。
- HUD 主装置图标来自领域类型，不能把兼容操作键 `energy_cannon` 当成当前总装配类型。

专题：[素材关系](asset_relationships.md)、[装备展示](equipment_presentation_modes.md)、
[矿物与装备叠层](mineral_rendering_and_equipment_layers.md)、[悬浮渲染](glory_item_hover_rendering.md)。

## 5. HUD 和窗口

免费版的批准范围见 [free_hud_rendering](free_hud_rendering.md)，不要扩大为所有 UI 免费版化。
固定原生像素并锚定四边；放大视口应增加地图可见范围。Godot 嵌入预览的固定尺寸/容器留边与
游戏伸缩是不同问题，先查编辑器设置，再决定是否改项目代码。

基线逐项记录：内容框（不是整张面板中心）、图像 origin、字体字号/字重、文字基线、
点击区域、悬浮边界、窗口开合/拖动/置顶。怪物名与底部血条对齐；tooltip 靠近实体/鼠标且受视口约束。
面板应非模态，不阻断地图操作。自动几何断言不替代真实字体/透明度截图验收。

## 6. 网络与经济

| 现象 | 先核对 | 不采用的“修复” |
| --- | --- | --- |
| 怪被提前扣血/弹体不同步 | tick 是否重复推进、实际炮参数、同 input_sequence 的两侧日志、服务器扫掠 | 调慢服务端、让客户端爆炸直接判命中 |
| 行走顿挫 | 输入确认与路线完成、唯一位置写入者、快照顺序、主线程资源阻塞 | 离线关闭预测/另写移动算法 |
| 进入后延迟跳图 | 存档目标图就绪与 bundle 提交、初始化重入 | 把出生点硬改为上次测试位置 |
| 入包错误 | 原始错误码、实例 ID、revision、存档与地图事务顺序 | 清空存档、关闭防重复校验、所有失败显示成功 |
| 换装备后数值不变 | 权威装配→战斗状态→CurrentPlayer→所有视图 | 只换一张图片或在面板单独计算攻击力 |

新奖励必须有跨重启稳定的唯一实例身份；同一次业务重试复用其幂等标识，不能每次重试随机生成新奖励。
当前采矿修复只解决跨模块生命周期 ID 碰撞，不能据此宣称全系统已有崩溃安全的经济幂等流水。
生产/购买/任务的成本、产物和经验在同一候选玩家聚合提交；界面只投影服务器结果。

## 7. 交付检查表

- [ ] 版本/来源/证据等级明确，生成脚本和业务路径可追溯。
- [ ] 配置实例化模型后，权威规则与所有展示读同一状态契约。
- [ ] 默认离线和独立服务器都使用相同用例；没有新增双时钟或本地结算旁路。
- [ ] 失败、重发、切图、断线、重启按风险覆盖；用户存档未被测试改写。
- [ ] 素材按需导入；无原路径泄漏、无截图裁切/AI 图充当正式原版资源。
- [ ] 有实际运行记录；区分单元、集成、实网和截图验收。
- [ ] 文档已登记，中文函数注释和小批提交门禁通过。

未登录原游戏时可以以源码与资源做高可信复刻，但不能冒充原版运行对照已完成。
