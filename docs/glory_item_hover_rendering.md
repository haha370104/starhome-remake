# 荣耀版物品悬停渲染逆向与复刻方案

## 1. 结论

荣耀版没有为人物面板、背包面板和战车装备面板分别实现三套物品悬停样式。三类物品最终都复用物品基类的鼠标事件：

- 鼠标进入物品：给物品本体增加绿色发光，原始参数为 `glow(#33FF00, 4)`；
- 同步创建物品说明；面板中的物品使用复杂属性说明，最终坐标为鼠标右移 10 像素、上移 20 像素；
- 鼠标离开物品：删除简单说明（如果存在），并把发光背景清空；
- 拖拽物品时使用半透明跟随图，而不是绿色悬停效果。

因此复刻工程应当实现一个可复用的“物品悬停表现”，绑定到三类面板里的实际物品图像上，而不应在三个面板中复制状态逻辑。

## 2. 原始客户端证据

### 2.1 共同物品基类

`cltobj/stuffclt.fcc` 中的 `testthing:img` 通过：

```text
#include "cltbasething.fcc";
```

引入通用物品行为。衣服类声明为 `cloth:testthing`，普通物品及大量装备也沿用这条继承链。

战车装备的基础类 `BaseEquip` 同样包含 `cltbasething.fcc`。能量炮虽然覆盖了 `OnMouseIn()`，但仍然使用相同的绿色发光参数和说明窗口分支。

### 2.2 鼠标进入和离开

`cltobj/cltbasething.fcc` 的通用逻辑是：

```text
void OnMouseIn()
{
    bk:=glow(#33FF00,4);
    ...
}

void OnMouseOut()
{
    ...
    bk:=null;
}
```

`cltobj/equipclt.fcc` 中能量炮的覆盖实现仍以 `bk:=glow(#33FF00,4)` 开始。这说明颜色和强度不是某个面板临时指定的，而是物品交互规范的一部分。

### 2.3 物品说明窗口

通用逻辑根据物品所在容器选择说明类型：

- 物品位于地图对象容器时，创建只显示名称的 `SimpleDesc`；
- 物品位于背包、人物装备或战车装备等面板时，调用 `ShowComplexDesc(...)` 显示完整属性；
- 调用入口传入 `mousexpos + 10, mouseypos`，荣耀版构造函数再执行 `pos=x,y-20`；最终位置是鼠标右移 10、上移 20；
- 新说明出现前会删除全局已有说明，避免多个说明叠放。

### 2.4 触发时序与存活规则

`OnMouseIn()` 直接执行 `ShowComplexDesc(...)`，创建前没有任何延时。构造函数中的 `TimerCall(1,"SetBk")` 只延后约 1 毫秒组装底板，不是 tooltip 延迟。Godot 默认 tooltip 的等待时间因此不符合原版。

说明窗的生命周期为：

- 创建后约 100 毫秒首次检查鼠标；
- 鼠标仍在物品上时，每约 1000 毫秒继续检查；
- 鼠标从物品移向说明窗时，说明窗自己的 `OnMouseIn()` 会锁住窗口；
- 离开物品和说明窗后删除；进入另一件物品时，新说明立即替换旧说明。

复刻应当同步显示，并保留约 100 毫秒的“跨越空隙”时间，让鼠标可以从物品移动到说明窗。

### 2.5 字体和底板

复杂说明的物品名称显式使用 `SETFONT2`：

```text
宋体，宽 6，高 12，字重参数 800
```

正文 `objdesc` 的文本区域宽约 195 像素，名称区域宽 218 像素；底板使用 `MiniFormStyle`，来源为荣耀资源 `pic3/interface/form/miniform.png#autofind`。复刻现使用共享微软雅黑 12px：标题采用粗体，正文采用常规字重，内容宽度约 218 像素，并使用深蓝底、青蓝边框的荣耀小窗样式。

### 2.6 拖拽不是悬停

`cltobj/stuffclt.fcc` 中的 `moveshadow` 会复制物品图像并设置：

```text
alpha=150;
follow:=mouse();
```

它表示拖拽期间的半透明跟随图。复刻时必须让拖拽透明度与悬停绿色发光成为两个可以叠加、互不覆盖的表现状态。

## 3. 三个面板的适用范围

### 3.1 人物面板

“物品”是人物装备槽中的衣服、裤子、鞋等装备图层。人物裸体底图和纯装饰背景不响应物品悬停。

### 3.2 背包面板

每个背包格中的实际物品响应悬停。空格、页签和翻页按钮不属于物品，不使用绿色物品发光。

### 3.3 战车装备面板

已安装的底盘、主武器、推进器、装甲、发生器、宏原子和三系特殊装备均响应悬停。固定槽位说明文字与面板背景不响应物品悬停。

## 4. Godot 实现方案

### 4.1 分层职责

- 领域层：继续由 `Player` 聚合根及其 `Inventory`、`CharacterEquipment`、`VehicleLoadout` 子对象维护物品位置和换装规则；不增加 `hovered` 字段。
- 服务端投影层：只输出物品身份、装备位置和展示资源等 DTO 数据；不处理鼠标状态。
- 客户端表现层：统一的 `ItemHoverHighlight` 将进入/离开信号绑定到可交互控件，同时控制图像材质和即时说明窗。
- 各面板：只负责指出“哪个控件接收鼠标、哪个 CanvasItem 被高亮”，不各自保存一套悬停状态机。

悬停属于瞬时本地表现，不应写入充血领域模型、存档或网络协议。

### 4.2 视觉近似

使用共享 `canvas_item` shader：

- 默认参数 `hover_amount = 0`，保持原图；
- 鼠标进入时切换为 `1`；
- 采样当前像素周围约 4 像素范围的 alpha，生成 `#33FF00` 轮廓/光晕；
- 对物品本体做轻微绿色增亮，保证透明边距很小的图标仍有清楚反馈；
- 鼠标离开时恢复 `hover_amount = 0`。

每个物品图像拥有自己的 `ShaderMaterial` 实例，避免一个物品进入时让同材质的所有物品同时发光。

### 4.3 状态组合

推荐状态优先级如下：

1. 是否锁定/不可操作决定输入是否被接受；
2. 拖拽状态继续通过控件透明度表现；
3. 悬停状态只控制 shader 参数，不直接改写 `modulate`；
4. 说明窗与发光由同一对鼠标进入/离开事件触发，但彼此不依赖；不再使用 Godot 延迟 tooltip。

这样可避免当前背包拖拽使用的 alpha 与新增绿色高亮互相覆盖。

## 5. 验收标准

- 人物、背包、战车装备三个面板中的所有实际物品均可单独高亮；
- 悬停一个物品不会点亮其他物品；
- 离开后恢复原始颜色；
- 背包拖拽透明度行为不变；
- 槽位文字、空格和人物裸体底图不会错误发光；
- 高亮不会触发领域命令、服务端请求或存档变更；
- 说明窗进入物品时立即出现，位于鼠标右侧 10 像素、上方 20 像素；
- 说明窗使用共享微软雅黑 12px，标题粗体、正文常规字重，宽度接近原版；
- 双击装备/卸下与拖拽操作继续可用。

## 6. 战车槽位文字精确对齐补充

`ButtonText(x,y,...)` 的 `pos=x,y` 是文字左上角，不是文字中心。荣耀版十四条文字必须直接使用源码坐标，不能像首版复刻那样再减去半个标签宽高，也不应强制居中。

- 字体：共享微软雅黑 12px，常规字重；
- 对齐：左对齐，位置直接取 `menupart_main.fcc:9830-9890` 的 `x,y`；
- 阴影：源码没有为这些 `ButtonText` 添加文字阴影；
- 交互：只有 `装置1` 的 `OnMouseIn` 将颜色改为 `#FFCC00`，其余十三条进入/离开都保持 `#FFFFFF`；
- 槽位文字没有 tooltip，业务语义仍由装备物品自己的复杂说明展示。

## 7. 首次显示的尺寸计算

`LegacyItemTooltip.set_content()` 必须先把标题和正文 Label 的实际宽度设为内容宽度 218px，再赋值文本、测量高度及定位。不能假设首次创建时 VBoxContainer 已完成排序：此时 Label 默认宽度为 0，自动换行可能把十三行装备说明误算成 1576px 高；下一次悬停才因布局宽度已确定而恢复正常。

保持即时显示，不通过延迟一帧或第二次悬停来修正尺寸。宽度仍为 234px（内容 218px + 左右各 8px），高度随文本收缩/扩展。此修复只影响共享说明窗布局，不改变字体、悬浮时机和业务数据。
