# 荣耀版物品悬停渲染逆向与复刻方案

## 1. 结论

荣耀版没有为人物面板、背包面板和战车装备面板分别实现三套物品悬停样式。三类物品最终都复用物品基类的鼠标事件：

- 鼠标进入物品：给物品本体增加绿色发光，原始参数为 `glow(#33FF00, 4)`；
- 同时在鼠标右侧约 10 像素处打开物品说明；面板中的物品使用复杂属性说明；
- 鼠标离开物品：删除简单说明（如果存在），并把发光背景清空；
- 拖拽物品时使用半透明跟随图，而不是绿色悬停效果。

因此复刻工程应当实现一个可复用的“物品悬停表现”，绑定到三类面板里的实际物品图像上，而不应在三个面板中复制状态逻辑。

## 2. 原始客户端证据

### 2.1 共同物品基类

`cltobj/stuffclt.fcc` 中的 `testthing:img` 通过：

```text
#include "cltbasething.fcc";
```

引入通用物品行为。衣服类声明为 `cloth:testthing`，普通物品及大量装备也沿用这条继承链。

战车装备的基础类 `BaseEquip` 同样包含 `cltbasething.fcc`。能量炮虽然覆盖了 `OnMouseIn()`，但仍然使用相同的绿色发光参数和说明窗口分支。

### 2.2 鼠标进入和离开

`cltobj/cltbasething.fcc` 的通用逻辑是：

```text
void OnMouseIn()
{
    bk:=glow(#33FF00,4);
    ...
}

void OnMouseOut()
{
    ...
    bk:=null;
}
```

`cltobj/equipclt.fcc` 中能量炮的覆盖实现仍以 `bk:=glow(#33FF00,4)` 开始。这说明颜色和强度不是某个面板临时指定的，而是物品交互规范的一部分。

### 2.3 物品说明窗口

通用逻辑根据物品所在容器选择说明类型：

- 物品位于地图对象容器时，创建只显示名称的 `SimpleDesc`；
- 物品位于背包、人物装备或战车装备等面板时，调用 `ShowComplexDesc(...)` 显示完整属性；
- 说明窗口起点使用 `mousexpos + 10, mouseypos`；
- 新说明出现前会删除全局已有说明，避免多个说明叠放。

当前复刻工程已经为面板物品生成属性 tooltip。本次保留这套数据内容和打开机制，只补齐原版的绿色悬停反馈；如果以后需要逐像素还原，再把 Godot 原生 tooltip 替换为跟随鼠标的自绘说明窗。

### 2.4 拖拽不是悬停

`cltobj/stuffclt.fcc` 中的 `moveshadow` 会复制物品图像并设置：

```text
alpha=150;
follow:=mouse();
```

它表示拖拽期间的半透明跟随图。复刻时必须让拖拽透明度与悬停绿色发光成为两个可以叠加、互不覆盖的表现状态。

## 3. 三个面板的适用范围

### 3.1 人物面板

“物品”是人物装备槽中的衣服、裤子、鞋等装备图层。人物裸体底图和纯装饰背景不响应物品悬停。

### 3.2 背包面板

每个背包格中的实际物品响应悬停。空格、页签和翻页按钮不属于物品，不使用绿色物品发光。

### 3.3 战车装备面板

已安装的底盘、主武器、推进器、装甲、发生器、宏原子和三系特殊装备均响应悬停。固定槽位说明文字与面板背景不响应物品悬停。

## 4. Godot 实现方案

### 4.1 分层职责

- 领域层：继续由 `Player` 聚合根及其 `Inventory`、`CharacterEquipment`、`VehicleLoadout` 子对象维护物品位置和换装规则；不增加 `hovered` 字段。
- 服务端投影层：只输出物品身份、装备位置和展示资源等 DTO 数据；不处理鼠标状态。
- 客户端表现层：统一的 `ItemHoverHighlight` 将进入/离开信号绑定到可交互控件，并控制对应图像的材质参数。
- 各面板：只负责指出“哪个控件接收鼠标、哪个 CanvasItem 被高亮”，不各自保存一套悬停状态机。

悬停属于瞬时本地表现，不应写入充血领域模型、存档或网络协议。

### 4.2 视觉近似

使用共享 `canvas_item` shader：

- 默认参数 `hover_amount = 0`，保持原图；
- 鼠标进入时切换为 `1`；
- 采样当前像素周围约 4 像素范围的 alpha，生成 `#33FF00` 轮廓/光晕；
- 对物品本体做轻微绿色增亮，保证透明边距很小的图标仍有清楚反馈；
- 鼠标离开时恢复 `hover_amount = 0`。

每个物品图像拥有自己的 `ShaderMaterial` 实例，避免一个物品进入时让同材质的所有物品同时发光。

### 4.3 状态组合

推荐状态优先级如下：

1. 是否锁定/不可操作决定输入是否被接受；
2. 拖拽状态继续通过控件透明度表现；
3. 悬停状态只控制 shader 参数，不直接改写 `modulate`；
4. tooltip 与发光由同一对鼠标进入/离开事件触发，但彼此不依赖。

这样可避免当前背包拖拽使用的 alpha 与新增绿色高亮互相覆盖。

## 5. 验收标准

- 人物、背包、战车装备三个面板中的所有实际物品均可单独高亮；
- 悬停一个物品不会点亮其他物品；
- 离开后恢复原始颜色；
- 背包拖拽透明度行为不变；
- 槽位文字、空格和人物裸体底图不会错误发光；
- 高亮不会触发领域命令、服务端请求或存档变更；
- 原有 tooltip、双击装备/卸下与拖拽操作继续可用。
