# 工程规范与客户端边界

本规范用于后续功能和本轮客户端重构。旧文档中的阶段计划不代表当前完成状态；实际边界以代码、测试和本文维护记录为准。

## 分层与依赖

| 层 | 职责 | 禁止承担 |
| --- | --- | --- |
| 入口 / application | 启动参数、依赖创建、信号连接、生命周期 | 命中选择、装备规则、切图事务、具体控件布局 |
| client/gameplay | 玩家输入意图、切图流程、交互协调 | 修改权威生命、背包和任务进度 |
| client/presentation | 将状态投影到世界与 HUD | 保存玩家、决定奖励、直接访问数据库 |
| client/ui | 窗口与可复用控件、语义信号 | 知道 main_hall、查找服务器节点、决定事务版本 |
| client/state | 唯一当前玩家投影、命令边界 | 窗口位置、节点创建、独立玩法规则 |
| domain / server | 领域不变量与权威事务 | 引用客户端 UI、依赖具体启动场景 |

依赖从入口向内。模块通过显式类型参数和业务信号协作，不传整个 main_hall，不使用任意 Dictionary 作为服务定位器，不通过 get_parent 链取业务依赖。禁止用继承或搬到一个巨大 ClientApplication 的方式隐藏入口复杂度。

## 状态与契约

- 本地路径、位置与预测输入只有 LocalPlayerController 一个写入者。
- ActiveWorldController 拥有活动地图；切图流程协调预载和权威确认，提交失败时冻结旧场景，不能继续产生输入。
- CurrentPlayer 是共享的只读客户端投影；窗口打开、关闭不改变它的生命周期。
- 可复用展示组件只接收展示数据并发出操作意图。人物槽位和战车 Location 的命令语义由各自面板负责。
- UI 不直接持有网络传输；命令适配器负责补齐 revision，所有玩法结果仍由同一权威服务器产生。
- HUD 对外提供状态提示、动作选择、地图和覆盖层 API；外部不访问 Label、内部 popup 或状态对象。
- JSON / RPC 的 Dictionary 在入口校验。已有快照、地图 bundle 字典作为明确列出的迁移债务保留；禁止借重构新增一个全局字典上下文。新领域接口使用类型化对象。

## 可读性与复用

- 按业务职责命名文件与目录；一个模块只有一个主要变更原因。共享组件放 client/ui/components，不能反向引用具体窗口。
- 组合优先：窗口壳负责拖动关闭，内容组件负责显示，控制器负责会话交互。只有稳定的共同窗口行为使用继承。
- 具名 GDScript 函数写中文契约注释：作用、参数、返回值，特殊时序说明原因；禁止重复函数名的模板注释。
- 文件长度是评审提示，不是拆分目的。入口以 300 行为上限，重构新增模块以 500 行为上限；超限必须先重新审查职责。
- 测试通过状态实际所有者进行断言；不能为了测试在入口重新堆积转发方法。

## 验收与交付

### 运行时字体

全游戏动态文字统一使用微软雅黑 UI；系统缺少该字体时依次回退到微软雅黑、苹方、思源黑体和系统无衬线字体。
`project.godot` 的 `gui/theme/custom_font` 与现有面板共同引用
`assets/ui/fonts/legacy_panel_font.tres`，粗体使用同目录的 `legacy_panel_bold_font.tres`。
这两个历史文件名为兼容既有引用而保留，内容不再是宋体。窗口不得自行创建另一套字体族。
本次替换保留各控件的字号和字重；任务日志使用正文 16px、标题 20px。
原图中烘焙的按钮字样属于图片内容，不受运行时字体设置影响。

### 地图导航

地图导航由小地图和 `Tab` 当前地图窗口共同提供。展开的小地图（包括跟随玩家滚动的小尺寸模式）
支持左键选点；`Tab` 打开或关闭地图面板，输入文字时保留输入控件的 Tab 行为。
面板右侧显示当前 NPC、设施和启用传送点的名称、世界像素坐标，单击即规划路线。
窗口保持打开也能行走，切图时替换底图和目的地集合；巡逻 NPC 坐标在面板可见时每 0.5 秒刷新。

实现边界：

- `MapProjection` 统一处理图片矩形、等比缩放、滚动偏移与世界坐标转换，底图外留白不发出移动。
- `MapNavigationCanvas` 与 `MapDestinationList` 是可复用控件，`MapNavigationPanel` 只组合界面和发布意图。
- `ActiveWorldController` 通过 `MapNavigationPoint` 发布不含节点引用的展示快照，地图提交后同步更新 HUD。
- `WorldInteractionController.navigate_from_map` 在点击时重新解析实时目的地，经已有 `move_to` 进入
  `LocalPlayerController` 的可达性校验、路径规划和网络移动意图流程，不新增位置写入者。
- 传送点展示 `source_anchor` 坐标，寻路使用 `approach_point`，保留 `transition_id` 供到达后执行原切图流程。
  同址多目的地保留独立列表项；旧地图失效标识不回退到旧坐标。
- GUI 消费地图点击，避免误触世界攻击；切图、击毁和无推进器限制继续由现有移动流程执行。

专项回归：`tests/ui/runtime/map_navigation_test.gd` 验证真实 GUI 输入与坐标投影，
`tests/integration/map_navigation_scene_test.gd` 验证当前实体、移动意图、到达出口和地图替换。
二者纳入 `tools/run_client_checks.py`。

### 世界点击与主装置

世界左键由 `CombatInteractionController` 按“掉落拾取 → 当前选中装置”分发。
掉落命中包括原始图片、四像素发光边缘及当前可见的名称，悬停与拾取共享判定；隐藏名称不保留命中范围。
只有选中主槽且实际安装采掘臂时才查询矿物并调用 `request_mining`，采矿技能与装备许可继续由领域模型校验。
能量炮和战术武器保留原开火流程，矿物不拦截它们的点击。
维修臂发布客户端 `target_repair_requested` 意图并提示目标维修尚未开放，不冒充已完成维修或发送采矿请求。
目标维修的服务器结算尚未实现；现有 `self_repair` 属于底盘自维修，是独立功能。
`tests/integration/combat_click_routing_test.gd` 使用真实掉落、矿物、目录装备和武器表现验证上述分发。

### 检查与提交

1. 改动前记录 Git 脏文件与可运行基线，保留用户尚未提交的修改。
2. 每个独立步骤运行相关领域、组件或集成回归。涉及输入顺序、同步回调、原子切图必须验证真实行为，不能只检查节点存在。
3. GDScript 导入及零警告、函数注释、文档链接和客户端边界检查作为工程门禁。测试保存到隔离目录，不使用日常玩家存档。
4. 改动窗口布局或交互时补充视觉检查。报告区分本次通过、未执行与环境限制。
5. 按现有约定独立提交：每次最多 20 个文件、文本增删合计 2000 行，提交前核对暂存路径和 numstat，不能混入用户修改或素材导入。

## 本轮范围

拆分客户端入口、切图、战斗和交互协调，统一 HUD 边界，抽取共享装备图层与背包内容，分离窗口管理和玩家命令状态。保持原素材、像素布局、协议与权威玩法。

服务器全面拆分、生产 SQLite、所有历史 Dictionary 类型化和全工程场景编辑器迁移是后续独立工程，不把它们描述为本轮已完成。
